# CLAUDE.md — контекст проекта для Claude Code

Claude Code читает этот файл в начале каждой сессии. Держи его коротким и актуальным:
поменял архитектуру — обнови файл («обнови CLAUDE.md под изменения»).

## Что это
**«Соберись!»** — чек-лист для сборов в поездку. PWA: ставится на iPhone/Android,
открывается в браузере на ноутбуке, работает офлайн, синхронизируется между устройствами
через облако. Вход — Google, доступ только у разрешённых аккаунтов.

**Кто пользуется:** один человек — с телефона и периодически с компьютера. Главный сценарий
синхронизации — телефон ↔ компьютер (в т.ч. правки на телефоне без интернета). Совместная
работа нескольких людей не нужна; не усложняй ради неё.

- Живой адрес: https://faxbax-ctrl.github.io/abkhazia-checklist/
- Репозиторий: https://github.com/faxbax-ctrl/abkhazia-checklist (**публичный**)
- Firebase-проект: `abkhazia-checklist`

## Технологии — НЕТ сборки, НЕТ фреймворков
- `index.html` — всё приложение: HTML, CSS (`<style>`), JS (`<script>`), внизу —
  `<script type="module">` с Firebase (Auth + Firestore, SDK v10 с CDN gstatic).
- `sw.js` — service worker: офлайн-кэш своих файлов и Firebase SDK. При установке файлы
  качаются мимо кэша браузера (`cache:'reload'`); новая версия применяется сама
  (`controllerchange` в `registerSW`: перезагрузка, а если открыто окно — кнопка «Обновить»).
- `manifest.webmanifest`, `icon-*.png` — PWA.
- Хостинг: GitHub Pages, ветка `main`. Правки — прямо в файлах, никаких `npm build`.

## ⚠️ Обязательные правила
1. **Менял `index.html` или `sw.js` — подними версию кэша** в `sw.js`
   (`const CACHE = 'abkhazia-vN'` → `vN+1`), иначе у людей останется старая версия.
2. **Не ломай схему `STATE`** — она лежит в облаке. Меняешь схему — сохрани совместимость
   (`migrate()`, `normalizeIds()`), помни, что старые версии приложения ещё могут писать в облако.
3. **Никаких секретов и личных данных в репозитории** (он публичный, история вечная):
   email-списков, адресов, личных файлов. Перед коммитом — `git status`.
4. После правок проверь, что приложение открывается и данные грузятся.
5. Бэкапы — в `_backup/` (в `.gitignore`, в репозиторий не попадают) + git-теги `backup/*`.

## Модель данных
```
STATE = { v:2, activeTripId, trips:[
  { id, kind?:'template', location, dateFrom, dateTo, createdAt, model:[        // поездка/шаблон
    { key, icon, tab, title, intro, groups:[                                 // категория
      { gid, emo, title, items:[ {id, t, n, done} ] }                        // подкатегория
      | { gid, sub }                                                         // заголовок-раздел
    ] } ] } ] }
```
- `MODEL` — всегда `model` активной поездки (`syncModelRef()`), `active` — ключ категории.
- Шаблоны — поездки с `kind:'template'`, все равноправны, без дат.
- **У всего есть id** (`trip.id`, `page.key`, `group.gid`, `item.id`) — по ним работают правка,
  сворачивание, перетаскивание и слияние. Индексы массивов для этого не использовать.
  Старым данным `gid` назначает `normalizeIds()` детерминированно (хэш) — одинаково на всех устройствах.
- `activeTripId` — у каждого устройства свой (выбор поездки в облако не пишется, `saveLocal()`).
- **Содержимого списка в коде НЕТ** — всё приходит из Firestore (ради приватности).

## Синхронизация (ключевое — не ломать!)
- В облаке один документ `checklists/shared`: `{ data: JSON(STATE), rev, updatedAt, writer }`
  (лимит Firestore 1 МиБ; предупреждение при 80% — `checkStorage`, индикатор — в Профиле).
- Локально (`localStorage`): `abkhazia_v2` — STATE, `_base` — версия облака, на которой он
  основан, `_rev` — её номер, `_dirty` — есть неотправленные правки.
- Правка → `save()` → `dirty` → `pushCloud()` → `doSync()`: **транзакция** читает облако,
  **трёхстороннее слияние** `mergeStates(база, наше, облако)` и запись. Одновременные правки
  с разных устройств не теряются; время устройств не сравнивается.
- **Пока не пришёл первый снимок из облака (`cloudSynced`) — ничего не пишем.**
- Снимок из облака → `onRemote()`: нет своих правок — берём облако; есть — сливаем.
  Во время перетаскивания всё откладывается (`whenIdle`, `pendingSnap`).
- Повреждённые данные из облака не сливаются (`validData`).
- Индикатор `#syncLbl` у прогресса: «⏳ ждёт связи» / «⚠️ не сохраняется в облако».

## Доступ и вход
- Вход — ТОЛЬКО `signInWithPopup` (redirect на iOS/standalone даёт «missing initial state»),
  `prompt:'select_account'`, ошибка → `onSignInError`.
- **Кто имеет доступ — только в правилах Firestore** (Console → Firestore → Rules), не в коде:
  `allow read, write: if request.auth != null && request.auth.token.email in [...]`.
  Добавить человека = добавить email в правила и Publish. `apiKey` в коде — не секрет.
- `onAuthChange` при каждом входе/выходе пересоздаёт подписку (`stopCloud`/`startCloud`).
- **Быстрый старт** (`quickStart` в конце скрипта): Firebase восстанавливает вход 1–2 с, поэтому
  если на устройстве уже входил аккаунт с доступом (`abkhazia_last_uid` + `abkhazia_ok_uid`) —
  список показывается сразу из памяти (и офлайн), вход подтверждается в фоне. Вышел из
  аккаунта (`last_uid` = '') — сразу экран входа; не знаем — заставка «Открываем…».
- Экран входа `#lock`: логотип — inline SVG (чемодан с галочкой), он же иконка вкладки.
- Устройство помнит аккаунты с подтверждённым доступом (`abkhazia_ok_uid`): им список
  показывается сразу (и офлайн), остальным — «Проверяем доступ…» до ответа облака.
  Нет доступа → `showDenied`.

## Где что в index.html
- **Шапка**: название поездки ▾ (`openTrips`), кнопки «Показать списком» (`openViewCurrent`),
  «Править» (`toggleEdit`), профиль (`openProfile`); прогресс, тумблер «Скрыть выполненные»
  (`toggleHideDone`, localStorage `hide_done`).
- **Рендер**: `render()` (страницы + нижняя навигация), `refresh()` (счётчики),
  `dispItems()` (порядок показа: выполненные вниз). Анимация страницы — только при
  переключении вкладки (`go`, класс `.anim`), не при каждом рендере.
- **Задача** — окно `#tsheet`: `openTaskEdit/openTaskNew/saveTaskSheet` (новая — вверх).
  Галочка — только по чекбоксу (`boxTap`): отмечается сразу, вниз уезжает через ~1 с.
  Удаление задачи — без вопроса, с «Вернуть» (`removeItemWithUndo`, подсказка `showToast`).
- **Шаблон** открыт → `body.tplmode`: без галочек и прогресса.
- **Пустая категория** — подсказка + «＋ Подкатегория» (видна всегда); в «Править» внизу
  страницы — «✎ Эта категория» / «＋ Новая категория».
- **Запоминается на устройстве**: открытая категория в каждой поездке (`last_cat`),
  свёрнутые подкатегории (`open_state`), «Скрыть выполненные» (`hide_done`).
- **Клавиатура** (компьютер): Esc — закрыть окно / выйти из правки; Enter — сохранить;
  в комментарии — Cmd/Ctrl+Enter.
- **Поездки/шаблоны** — экран `#trips`: `renderTrips`, `openNewTrip/openNewTemplate/openEditTrip/`
  `saveSheet/duplicateTrip/deleteTrip/makeTemplateFromTrip/switchTrip`.
- **Категории** — в Профиле (`openCatEditor/deleteCategory/renderProfileCats`);
  **подкатегории и заголовки** — в «Править» (`openGroupEditor/openSubEditor/deleteGroup`).
  Эмодзи-пикер `#esheet`.
- **Окна (bottom-sheet)**: `openSheetEl/closeSheetEl`; блокировка фона — счётчик `lockScroll`.
- **Перетаскивание**: `drag`, `onDragMove/onDragUp`, плейсхолдер `.drag-ph`. Итог берётся
  из порядка на экране (`collectOrder` → `apply*Drop`); не сдвинули — ничего не пишем.
  Виды: задачи, подкатегории, категории (в профиле), шаблоны.
- **Даты**: `fmtRange`, `countdown` (обновляется при возврате в приложение);
  `sortTrips`: идущие и ближайшие сверху → без дат → прошедшие.
- **Профиль**: имя (на устройстве, по умолчанию — из Google) только для значка;
  категории; заполнение облака; выход.
- **Доступность**: зум пальцами разрешён (поля ввода ≥16px, чтобы iOS не приближал сам),
  у кнопок-иконок есть `aria-label`, приглушённый текст — контраст ≥4.5.

## Деплой
`git push` в `main` → GitHub Pages (~1 мин). Проверять на живом адресе
(обход кэша — `?v=что-то`). После деплоя каждое устройство обновится при следующем запуске.

## Рабочий цикл
Небольшая правка → проверка → diff → коммит с понятным сообщением → push → проверка
на живом адресе. Сломалось — откат через git.
